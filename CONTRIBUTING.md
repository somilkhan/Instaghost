# Contributing

Thanks for helping improve InstaGhost.

## Before opening a change
- Check the open issues and pull requests for overlap.
- For larger changes, describe the problem and intended approach first.
- Keep changes focused and independently reviewable.
- Avoid including personal data, credentials, session material, or third-party APKs.

## Development
- Kotlin and Android conventions used by the project should be followed.
- Run unit tests, lint, and debug assembly when possible.
- Include tests for new behavior and regression fixes.
- Document assumptions, limitations, and validation status.
- Device validation is separate from CI validation. Record device and app version when testing on-device.

## Pull requests
Describe the problem, solution, limitations, and verification performed. Mark anything unverified clearly. Do not claim compatibility without evidence.

## Privacy and safety
Contributions should prioritize transparency, user control, privacy, stability, and documented behavior. Avoid covert or deceptive manipulation of activity signals or mechanisms designed to evade security and privacy protections.
